# Collection sufficiency

Collection sufficiency asks whether the existing operational portfolio can produce the evidence a detector needs. It is separate from opportunity qualification and execution authorization.

Epic 26A uses only real evidence packages, open evidence gaps, collection targets, target evidence, and latest persisted planning decisions. It reports observable breadth, depth, source independence, freshness periods, rights, conflicts, processing needs, and known blockers. It does not invent a market denominator, infer provider costs, or estimate time-to-sufficiency without defensible cadence and history.

The collection plan is advisory. Provider calls are always false and any new collection, target expansion, source enablement, or authorization requires operator approval. The provider control plane remains authoritative for credentials, rights, configuration, limits, schedules, and paid execution.

- **No new spend** waits for already-authorized observations and runs deterministic downstream processing.
- **Review required** leaves new or paid collection costs unknown until reviewed and explicitly authorized.

Re-evaluation requires no provider call: run `gis-opportunities diagnose` or reload Opportunities after existing ingestion, demand, and evidence processing completes.
